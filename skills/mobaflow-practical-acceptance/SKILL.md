# MOBAflow practical acceptance

Use the existing acceptance criteria and assigned scope. Bind each case to the exact package, commit, or deployment and record the platform, input method, and environment. Select scenarios that exercise the changed behavior, such as actual keyboard traversal, a required screen reader, text scaling, themes, or authorized device controls.

Record setup, user action, expected behavior, observed result, and evidence for each case. Identify whether evidence came from direct observation, a human report, or an automated check. Mark each case passed or failed only with an observed result. Use blocked for a concrete impediment and not run for an outstanding case.

Separate planning from execution. Verify that the assignment authorizes launching the app or operating a device before doing so. Keep automated results distinct from practical acceptance. Report outstanding cases with owner and next step for the existing acceptance matrix. Return evidence to the assigned acceptance owner and Project Manager through the existing handoff.
