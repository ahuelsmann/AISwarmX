# Small-batch delivery for MOBAflow

The development team uses this workflow for work on MOBAflow across **Claude Code**, **ChatGPT Codex** and **Antigravity**. Small batches on `main` were adopted on 2026-11-16 ([MOBAflow PR #468](https://github.com/ahuelsmann/MOBAflow/pull/468)) and expanded on 2026-11-17 into the multi-model agent network ([MOBAflow PR #479](https://github.com/ahuelsmann/MOBAflow/pull/479) and [PR #483](https://github.com/ahuelsmann/MOBAflow/pull/483)). See the [team manifesto](../manifest.md) for the compact overview and the [MOBAflow master coordination guide](https://github.com/ahuelsmann/MOBAflow/blob/main/.github/instructions/master-coordination.instructions.md) for the full operating rules, exceptions and gate commands.

## Capability profiles and risk classes

Roles define domain responsibilities and survive model updates (`Role != single model`). Every role and slice team draws on four capability profiles strictly from the [approved AI models catalog](allowed-models.md): `P1` Depth, Architecture & Safety (**`Opus 5.5`** ceiling in `MOBAi Claude Opus` or Antigravity's separate `MOBAi Antigravity Opus` plan); `P2` Repo, Build & Fact Precision (**`GPT-6.2 Sol`** & **`GPT-6.2 Astra`** workhorse sub-agents in `MOBAi ChatGPT Codex`, plus **`GPT-OSS 120B`** failover in Antigravity); `P3` System Context, Product & UI/UX (**`Gemini 4 Carbon`** in `MOBAi Antigravity Gemini`); `P4` Cadence, Triage & Fast Delivery (**`Sonnet 5.5`** and **`Gemini 4 Hydrogen`**, plus **`Claude Haiku 4.5`** strictly for Claude Code read-only `Explore` searches; **`Claude Fable 5.2` is prohibited**). **`Fresh Independent P1 Final Reviews`** default to Antigravity's `Opus 5.5` pool (Google AI plan) when partner quota is available (failing back cleanly to `Claude Code` when `0%`) to shield `MOBAi Claude Opus` (Anthropic plan) for COO intake and board steering. During a `Claude Code` quota pause, `MOBAi ChatGPT Codex` (`P2`), `MOBAi Antigravity Gemini` (`P3`), and `MOBAi Antigravity Opus` (`P1 Acting COO`) run `2/3 Quorum Failover` while keeping strict cross-family diversity. See [AI-DEVELOPMENT.md](https://github.com/ahuelsmann/MOBAflow/blob/main/docs/AI-DEVELOPMENT.md#capability-profiles-and-models) for the live mapping.

- **`H` High (Safety, Runtime & Protocol):** `Backend`, `Common`, `MOBApi`, `MOBAdisplay` (`esp32/`), project-switch/stop logic, runtime/protocol dependencies. Design Go and per-commit companion review across `P1` + `P2` (different model family from writer); safety veto is binding.
- **`M` Medium (Features, UI & Audio):** `MOBAflow`, `MOBAsmart`, `SharedUI`, `TrackPlan.*`, `Speech.*`, `Sound`, `MOBAnews`, UI/feature dependencies. Cross-family companion review from the design note on, plus `P3` Head of UI/UX at the design note for UI, TrackPlan and editorial slices.
- **`L` Low (Docs, Wiki & Small Non-Behavioral Fixes):** `docs/`, `docs/wiki/`, `specs/`, test/tooling-only dependency updates, `<=3`-file fixes without behavior change. States intent in the PR body/commit instead of a separate design note or per-commit companion. Review-fix rounds retain their slice's risk class and dependency updates take the class of the affected area.

## Coordinate work

- The **Decision & Steering Triad** (`P1` COO + `P2` CPM/TD + `P3` Product/UX) steers slice cutting, risk classification and the design Go. The **COO (Claude)** coordinates slice status on the [MOBAflow GitHub Kanban Board](https://github.com/users/ahuelsmann/projects/1) ([KANBAN.md](https://github.com/ahuelsmann/MOBAflow/blob/main/docs/KANBAN.md)) and records each slice's risk class, slice team and locked areas on the `MOBAflow` issue and Draft PR (`ahuelsmann/MOBAdev` manages only versioned AI configuration). The **CPM/TD (Codex)** prioritizes the backlog with the COO and can veto a slice or lock within 30 minutes.
- **Issue pull lifecycle (`Planned` → `Ready` → `In progress` → `In review` → `Done`):** Keep `Ready` focused on the top **`2–3` prioritized slices** (`Planned` holds the remaining backlog). Moving an issue from `Planned` to `Ready` authorizes `MOBAi Claude Opus` (`COO`) — as the sole intake owner — to pick it up once Code WIP (`< 3`) and domain locks allow. **3-World Parallel Track Distribution:** Distribute available disjoint Code WIP slots across all 3 active quota pools simultaneously (`Claude`: Backend/Host/Architecture; `Codex`: `MOBAdemo/app` React/TypeScript, CI/Build/Specs; `Antigravity`: `MOBAflow` WinUI/XAML/Themes, `TrackPlan`, `Class L` Wiki/Help & `P3` UI/UX reviews). Keep epic umbrella issues visually separate from single-slice WIP, start `needs-specification` issues with analysis + maintainer decision proposals rather than premature code, and leave the local MOBAdev dashboard strictly read-only.
- **GitHub-as-Mailbox Rule & State-Deduplicated Bus:** Post design notes, review findings, and blockers on the `MOBAflow` issue and coordinate real-time branch reviews (`base_sha..head_sha`) across tools via `mobai-swarm-bus` (plus `codex.exe queue` / `bus_send(..., wake: true)` for Codex). Pass the `state` parameter on `bus_send` whenever publishing recurring status updates so identical `(sender, recipient, topic, pr, issue, state)` messages deduplicate automatically.
- **Session-Start Resume & Work Queue (`bus_queue`):** At every session start or restart, inspect `bus_inbox` and call `bus_queue(action: "next", agent: "<head>")` before taking new work. If the session already holds an active `'claimed'` row (`lease_expires_utc > now`), `bus_queue` returns it (`resumed: true`) and renews its 4-hour lease; expired leases become claimable by another head. Watchdog preserves active `'claimed'` leases while an issue is `In progress` / `In review` until a `Closes #N` commit lands on `main` or the issue reaches a terminal state (`Closed` / `Done`). Unclassified items (`risk_class` null/empty) are treated as code (`H`/`M`) for WIP accounting: whenever `effectiveCodeWip = meta.code_wip + activeClaimedCodeCount >= 2` (in PR-free mode, open code PRs are `0` and `code_wip` tracks active claimed `H`/`M`/unclassified leases), `bus_queue next` skips `H`, `M`, and unclassified items and permits only `L`-class work.
- **4 standing Root Head sessions (`MOBAi`), ephemeral task agents:** The cockpit keeps **4** standing monitoring/steering sessions: **`MOBAi Claude Opus`** (`COO` `P1` `Opus 5.5` in Claude Code), **`MOBAi ChatGPT Codex`** (`Technical Director & CPM` `P2` `GPT-6.2 Sol` in ChatGPT Codex), **`MOBAi Antigravity Gemini`** (`Head of AI Strategy` `P3` `Gemini 4 Carbon` in Antigravity), and **`MOBAi Antigravity Opus`** (`Acting COO & Fresh P1 Opus Orchestrator` `P1` `Opus 5.5` in Antigravity). Regular intake starts in `MOBAi Claude Opus` (`COO`), while fresh independent `P1` final reviews default to Antigravity's `Opus 5.5` pool. All task-specific writers, companion reviewers, final reviewers and domain specialists (`Head of UI/UX`, `Head of MOBAnews`, `Security`, `DevOps`) are created automatically at task runtime with their profile model (`P1`–`P4`) and archived or removed (with their worktree) immediately after completion.
- The **Head of AI Strategy** (`P3` / `MOBAi Antigravity Gemini`) monitors multi-model orchestration quality, evaluates pilots ([ai-strategy-and-pilots.md](ai-strategy-and-pilots.md)), guards [manifest.md](../manifest.md) and keeps agent backups current in `MOBAdev`.
- A slice addresses one concern and can merge independently. Aim for at most about 25 files or 400 changed lines on one isolated task branch (`opus/...`, `codex/...`, `antigravity/...`). Only the named writer pushes to the task branch; Master-merge onto `origin/main` is performed by the Master session.
- Keep at most three code slices open (with active queue reservation capped at `effectiveCodeWip < 2` for new claims) and at most two local builders running. Code slices use disjoint `bus_locks`. Documentation-only (`Class L`) slices lock their edited files and do not count toward the code limit.
- Record locks, risk class, slice team, design decisions, handovers, merges and escalations on the `MOBAflow` issue and `mobai-swarm-bus` with UTC time and role, and keep status synchronized on the [MOBAflow GitHub Kanban Board](https://github.com/users/ahuelsmann/projects/1).

## Deliver a slice (PR-free Master-merge workflow)

GitHub Pull Requests are disabled (`has_pull_requests: false`) across `ahuelsmann/MOBAdev`, `MOBAflow`, and `SentiX`. Slices are delivered via isolated task branches reviewed over `mobai-swarm-bus` and squash-merged onto `main` by the Master session:

1. **Worktree, Task Branch & Locks:** Create an isolated worktree (`artifacts/worktrees/wt-*` or `-wt/*`) on a task branch (`opus/...`, `codex/...`, `antigravity/...`) from `origin/main` and claim disjoint `bus_locks`. For class `H` and `M` slices, post a 10–20 line design note on the `MOBAflow` issue and wait for cross-family Design Go (`Class M` slices whose scope, locked paths, and acceptance tests are already fixed in an approved Spec Kit `plan.md` may start directly with TDD).
2. **Local Verification on the Task Branch:** Write acceptance tests first for new behavior, then run local `Release` builds (`net10.0` and `net10.0-windows10.0.22621.0` with `-p:MobaAnalyzerGate=true`), `Test-AnalyzerBaseline.ps1`, `Test-LineEndings.ps1`, `Test-DocumentationLinks.ps1`, `Test-DocumentationConsistency.py`, relevant `dotnet test -c Release --no-build` / `node --test`, and `sonar analyze secrets`. Before handing over, merge `origin/main` into the branch (never rebase shared branches) and rerun affected checks.
3. **Push Task Branch & Cross-Family Bus Reviews (`base_sha..head_sha`):** Push the task branch to `origin/<branch>` and run independent cross-family `P1` (`Claude Opus 5.5`), `P2` (`Codex`), and `P3` (`Antigravity` for UI/editorial) reviews via `mobai-swarm-bus` bound to `base_sha..head_sha` (claim `(target_id, head_sha, role)` via `bus_review_claim` where supported). Final reviews MUST be cross-family (`claude` / `openai` / `gemini`) and follow the non-orchestrator dispatcher rule, using the bus-message verdict format:
   `moba-final-review verdict=PASS|CHANGES base=<40-char sha> head=<40-char sha> reviewer-family=claude|openai|gemini dispatcher=<head-name>`
4. **Master-Merge Squash & Post-Merge Monitoring:** Once cross-family verdicts `PASS` and local gates are green, the Master session squashes onto `origin/main` (`Closes #<id>` / `Refs #<id>`), fast-forward pushes `origin/main`, deletes the remote task branch (`git push origin --delete <branch>`), releases explicit `bus_locks`, and monitors post-merge `main` CI & SonarCloud.
5. **Cleanup:** Enforce **Branch & Worktree Hygiene** directly after merge: remove the slice worktree, delete the local branch, and run `git fetch --prune` (or `pwsh -NoProfile -File C:\Repo\ahuelsmann\MOBAdev\scripts\Invoke-RepoHygiene.ps1`; see [Hygiene & Zero-Token Automation](hygiene-and-automation.md)). Record affected developer documentation and user wiki pages or why they need no change.

## Restore the setup

Use the [rebuild runbook](rebuild.md) and [versioned agents guide](../agents/README.md) to configure each role on a new machine. In a MOBAflow checkout, follow the project's [AGENTS.md](https://github.com/ahuelsmann/MOBAflow/blob/main/AGENTS.md), Claude entry point and repository skill paths. For each tool, verify the effective instructions and loaded skill revision separately. The [setup inventory](setup-inventory.md) tracks the remaining verification. App, device and hardware actions require explicit maintainer authorization.
